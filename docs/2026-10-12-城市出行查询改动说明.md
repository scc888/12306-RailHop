更新日期：2026-10-12
项目：12306-RailHop（铁跃）
开发分支：`codex/transfer-query-20261010`

## 1. 这次要达到的效果

输入出发城市、目的城市、出行日期和可接受席别，即可查询到达目的地的路线。当所选席别没有直达票时，继续寻找同车接续或同站中转方案。

网站只做查询，展示实际车站、车次、日期时间、各段余票、席别及价格。优先展示全程各段有票的路线；本次搜索未找到这类路线时，保留用户原始设计中的“先买短途票，上车后申请补票”作为可选备选。备选只能确认有票区间，不能把后续待补票区间视为已经确认可行。

**2026-10-12 用户补充确认：保留有条件的补票备选。** 此要求修正了此前将“买短补长”整体移除的设计；已恢复为独立、有条件的备选查询，并完成样本及浏览器验证。

**2026-10-12 用户补充确认：默认推荐应避免明显绕路。** 北京到上海不应默认推荐先到长春再折返；优先搜索顺路中转站，较大绕行由用户主动选择，手动指定站可例外。已实现默认过滤、主动扩大范围及指定站例外，并完成回归验证。

### 三种查询结果

| 方式 | 用户看到的结果 | 校验重点 |
| --- | --- | --- |
| 直达 | 一趟车从出发城市内的实际车站到目的城市内的实际车站 | 实际起终点、乘车日期、所选席别有票 |
| 同车接续／车内换座 | 同一趟实际运行列车分成连续区间，各区间分别选择席别 | 同一运行列车、区间无缺口、跨日正确、每段均有票 |
| 同站中转 | 在同一个实际车站换乘另一趟列车 | 中间电报码一致、各段有票、满足本站换乘条件和时间 |

首末站可以扩大到城市范围；中途仍按此前确认的要求，仅接受同站换乘。

上述三类全程有票结果之外，另设“短途有票，后续需申请补票”备选区，展示已查到有票的区间、原票到站及后续待补票区间，不计入全程有票路线数量。

## 2. 检查中发现的问题

| 当前问题 | 对使用的影响 | 本次处理 |
| --- | --- | --- |
| 直达与中转分属两个表单，同车换座藏在单个车次中 | 用户需要重复填写和逐个展开，难以比较替代路线 | 统一查询入口，集中展示三类结果 |
| 城市名称实际落成单个车站查询 | 可能遗漏同城其他车站，比如武汉的汉口、武昌 | 使用官方字典中的城市归属，明确城市／单站范围 |
| 中转候选使用固定名单，缺少路线方向与绕行限制 | 北京到上海可能出现先到长春的明显绕路方案 | 按起终点筛选顺路候选，默认过滤明显绕行，用户主动选择后才扩大范围 |
| 旧“买短补长”只检查前一段有票 | 后半段可能无法继续乘坐，不能证明可到达目的地 | 保留为单独的有条件备选，明确有票终点、待补票区间及可能需要下车，不列为全程有票方案 |
| 旧同车算法仅按显示车次匹配 | 可能混入不同运行日、其他实际车站的数据 | 核验内部车次、运行日和准确电报码 |
| 跨午夜的后续区间仍使用起点日期 | 可能查错一天，拼接出不存在的行程 | 按区间实际历时与经停信息计算各段日期 |
| 余票判断可能把“0”“候补”等当成有票 | 推荐出没有现票的席别 | 只接受“有”或正整数，并检查可售状态 |
| 手机中转表单过长，按钮在底部 | 查询前需要较多滚动 | 常用条件和查询操作前置，高级条件折叠 |
| 页面固定显示“已就绪”及补票宣传文案 | 容易误解接口状态和路线可靠性 | 使用实际加载／失败状态，说明只查询及路线条件 |

## 3. 功能调整方案

### 3.1 一次填写，按需要查询

统一输入出发地、目的地、日期、列车类型和可接受席别。

- 默认“智能查询”：先查直达；所选席别没有直达结果时，继续查同车接续和同站中转。
- 本次搜索未找到全程有票方案时，提供“查看短途有票／补票备选”的可选入口；若上游失败或搜索不完整，必须同时说明，不能声称其他方案已经全部查完。
- 支持主动查询全部方式，或仅查询直达、同车接续、同站中转。
- 列车类型保留“全部、高铁动车、普速”，全部类型支持混合中转。
- 结果按类别展示，能够比较全程耗时、到达时间和所选席别总价。

### 3.2 区分城市和具体车站

- 出发地、目的地分别允许选择城市范围或指定车站。
- 同城关系来自 12306 站点字典的城市代码、城市名称字段，不通过站名前缀猜测。
- 结果展示实际乘车站，避免只写“上海”“北京”而让用户误解上车地点。
- 城市查询会接纳官方代表站查询返回的同城实际车站；该方式不等于遍历所有站对，页面必须披露覆盖限制。

### 3.3 同车接续严格验证

- 只返回每一段均查到所选席别余票的连续区间。
- 使用内部车次与运行日核对实际列车，不能只看 G、D、K 等显示车次号码。
- 核验实际起终点电报码，避免把同城不同站拼接为同车连续区间。
- 各段保留完整日期时间，处理跨午夜及多日历时。
- 计划提供最多 2 或 3 段同车接续，对应最多 1 或 2 次席位接续。
- 同车接续不套用站内换另一列车的最少换乘分钟数；是否需要换厢、经站台，以实际席位及工作人员指引为准。

### 3.4 同站中转继续保留原有要求

- 支持选择 1～3 次同站换乘。
- 支持按顺序输入指定中转站。
- 默认采用各站已采集的官方参考换乘时间；没有适用数据时，基础参考回退到 15 分钟。
- 自定义最少时间时，采用个人值与适用官方值中的较大值。
- 继续校验便捷换乘资料、实际同站和当前资料限定的同日到发条件。
- 中转站必须同时满足路线合理性要求，不能仅因有便捷换乘资料且两段有票，就默认推荐明显绕路的组合；详见 3.7。

### 3.5 席别与价格

- 默认包括二等座、一等座、硬座、硬卧、软卧，无座不默认勾选。
- 每段可以分别改选该段有票的席别，并即时更新总价。
- 金额使用整数“分”计算，避免小数累加误差。
- 查不到价格时显示“票价待确认”和已知部分金额，不按 0 元处理。
- 选择的是席别，不是具体座位号，也不承诺分段后仍是同一个座位。

### 3.6 保留短途有票、后续申请补票的备选

- 用于未找到全程有票路线时的备选查询，保留用户最初“先有一张票上车，再申请补票”的需求。
- 只展示同一实际列车继续经停目标站的候选；准确核验前段乘车日期、实际上车站、原票到站和所选席别余票。
- 明确展示“已查到有票：A→B”“后续需申请补票：B→C”，B 是原票到站，不能仅把整条路线标为“A→C 有票”。
- 必须在原票到站前向列车工作人员提出补票申请；有运输能力时才可办理，是否允许继续乘坐由铁路现场决定。
- 如补票申请被拒绝，应在原票到站下车；不得暗示可以未经允许继续乘坐。
- 前段座位／卧铺仅适用于票面区间，不承诺后续有座、同席别或继续使用原席位。
- 展示已知前段票价；后续补票金额未确认时标为“待确认”，全程总价同样待确认，不按 0 元合计。
- 此类结果单独展示和计数，不参与全程有票路线的最快／最低总价排名，不标注“保证到达”“必能补票”等承诺。
- 网站仅查询和说明条件，不办理购票或补票。本轮已接入独立查询入口、结果模型及卡片，并验证前段有票和全程未知价格。

### 3.7 中转路线合理性与绕行控制

- **默认优先顺路。** 按本次起终点位置、可核实的铁路线路／经停关系及实际时刻，选择与行程相关的候选站；不再把固定名单中的所有站以相同方式用于每个城市对。
- **先过滤，再排序。** 对明显偏离行程、折返或全程耗时过长的自动推荐进行过滤，再按用户选择的耗时、到达时间或价格排序；切换“价格最低”也不能重新混入默认已排除的明显绕路路线。
- **结合距离与时间。** 绕行判断应结合累计路程／地理偏离和含等待的全程耗时。地理距离可辅助筛选，不能将直线距离冒充实际铁路里程，也不能只按城市南北方向排除合理的铁路走向。
- **多次中转看整条路线。** 1～3 次换乘均检查累计绕行和整体走向，避免每一段单独看似合理，拼接后却大幅折返。保留重复站与循环路径限制。
- **较大绕行由用户选择。** 正常范围未找到结果时，提供“允许较大绕行”的可选入口，默认关闭；用户开启后才扩大候选与绕行范围，并重新查询。即使扩大范围，仍须满足余票、实际同站、官方参考换乘时间等规则。
- **扩大范围结果明确标识。** 展示实际经由站、全程含等待时间及绕行提示，不与默认顺路结果混淆，不暗示这是常规推荐。是否接受由用户判断。
- **手动指定站可例外。** 用户明确指定偏离方向的中转站时，可以按其要求查询，并提示可能明显绕行；例外仅针对绕行偏好，不能放宽有票、同站、换乘时间等硬条件，也不能在无可行方案时拼造结果。
- **规则可解释、数据有依据。** 实施时记录候选站筛选依据、距离／时间阈值与适用范围，避免无依据硬编码城市黑名单。缺少坐标、里程或参考时刻时不能按零距离、零耗时处理，应采用保守策略并披露限制。
- **不把有限搜索说成无路可走。** 正常范围无结果只说明本次范围内未找到；若查询失败或达到预算上限，应同时提示。增加顺路候选仍须来自有便捷换乘依据的车站，不承诺全国穷举或全局最优。

典型验收场景：查询北京→上海、未指定中转站且未开启较大绕行时，不应出现北京→长春／长春西→上海的默认推荐。用户开启较大绕行或明确指定长春后，才可在其他条件满足时展示该路线，并标注绕行。

这是产品的路线合理性策略，与 12306 的乘车规则分别校验；“有票且符合乘车条件”不等于“值得默认推荐”。本轮已生效。阈值、数据出处、保守排除策略及样本验证见[本轮验证记录](superpowers/journey-query-validation.md)。

## 4. 12306 规则如何体现在产品中

1. **补票备选按条件展示。** 12306 公布的规程说明，要求越过票面到站继续乘车，须在原票到站前提出；有运输能力时可以办理，无运输能力时可以拒绝补票和继续乘车。因此保留“前段有票，后段申请补票”的备选查询，但不将其列为已确认的全程有票路线；申请被拒绝时应在原票到站下车。[12306 公开规程](https://kyfw.12306.cn/otn/gonggao/saleTicketMeans.html?linktypeid=means5)
2. **同车接续必须是同一实际列车的连续有票区间。** 铁路部门的同车接续说明支持将同一列车不同区段余票组合为接续方案。[上海局官方说明](https://m.thepaper.cn/newsDetail_forward_29181361)
3. **不把“不下车”写成无条件保证。** 中国铁路说明，显示车次可能在途中变化；重联列车的部分车厢不互通，换厢可能需要经站台。[中国铁路说明转载](https://www.chinanews.com/sh/2026/05-28/10629996.shtml)
4. **参考时间和余票都有适用边界。** 换乘时间为已采集参考数据，余票为查询时快照，不能代表实时晚点、检票截止时间或通道开放状态。结果会保留资料来源与查询范围。

“符合规则”在这里指按已核实规则筛选路线并明确适用条件，不表示获得铁路官方认证，也不保证未来出行时余票或现场状态不发生变化。

**范围限制与实施判断：** 当前便捷换乘资料12站；同车最多核对4个车次，城市代表站查询不等于所有站对穷举。绕行距离采用GeoNames的332城快照代理，不能冒充铁路里程；默认阈值为基准距离1.7倍＋150公里，耗时上限为36小时与“基准距离／50公里每小时＋12小时”的较大值。缺失或歧义坐标保守排除自动候选，因此可能漏掉可行路线；用户可指定站或主动扩大范围。手动例外只覆盖指定路径带来的必要偏离，额外自动站仍受累计限制。有限搜索不承诺全国最快／最低价。

**补票规则边界：** 此次实现只查询有条件备选，不能验证未来列车运输能力；未进行实际补票办理。真实查询也不证明现场遇到了“全部直达无票”情形，该触发和各类失败／跨日条件由固定样本验证。

详见[本轮验证记录](superpowers/journey-query-validation.md)，其中区分固定样本、浏览器检查与真实接口证据。

## 7. 验收标准

- [x] 输入城市后能识别官方同城车站，并清楚展示实际上、下车站。
- [x] 直达无票时可自动查询替代路线，不需要重复填写条件。
- [x] 全程有票结果不包含待补票区间、候补或零余票；有条件补票备选独立展示和计数。
- [x] 未找到全程有票结果时，可选择查看短途有票／补票备选；查询失败或范围不完整时仍明确披露。
- [x] 补票备选正确区分有票区间、原票到站和待补票区间，展示到站前申请、有运力才可办理、被拒绝须按原票到站下车的条件。
- [x] 补票备选不承诺后续有座、原席位延续或必能到达；未知补票金额与全程总价标为待确认。
- [x] 同车接续不串车、不串日、不混同城异站，区间完整相连。
- [x] 中转严格同站，满足指定站顺序和适用换乘时间。
- [x] 北京→上海在默认设置、未指定站时，不推荐经长春／长春西大幅折返；未查到顺路结果时也不能自动加入该路线。
- [x] 顺路且满足余票、同站及时间条件的路线仍可进入结果；筛选不能仅凭南北方向误排合理线路。
- [x] “允许较大绕行”默认关闭，开启后重新查询并明确标识绕行；价格排序不能绕过默认绕行过滤。
- [x] 手动指定长春等偏离行程的站时，允许查询并提示绕行，但仍严格校验余票、同站与换乘时间。
- [x] 2～3 次中转按全程累计绕行判断，不能通过拆成多段绕过限制；缺失距离／时间依据不按零值处理。
- [x] 所有路线支持席别展示、正确计价与缺价说明。
- [x] 查询失败与确定的空结果区分；有限范围搜索明确提示不完整。
- [x] 更改条件或取消后，旧响应不能覆盖当前结果。
- [x] 桌面和手机布局可用，查询按钮易找到，无横向溢出。
- [x] 完成本轮后端、前端、构建和浏览器验证，记录真实查询证据及局限。
