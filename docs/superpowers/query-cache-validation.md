# 查询替换与 PostgreSQL 缓存验证（2026-10-21）

## 行为与原因

原前端在 loading 时禁用查询按钮并跳过提交；后端 journey/transfer 接口共用
`transfer_lock`，旧任务即使已被浏览器取消，仍会导致新请求返回 429。

已移除两处限制。新查询沿用已有 AbortController 和序号机制，使旧响应无法覆盖新结果。
每次请求独立创建客户端、Cookie 会话、中转网关及规划器，结束后关闭会话；公开铁路数据共享缓存。
原工作区两个旧组件的删除状态未改动。

## 缓存范围

- 内存容量默认 2048 项，可选 PostgreSQL 共享存储；数据库不可用时回退，查询仍可继续。
- 余票按日期、实际查询站对、票种缓存 15 秒；运行日期保留，返回模型独立复制。
- 经停时刻表按列车、日期、实际站对缓存 12 小时。
- 成功的空结果可缓存；异常、错误业务状态、格式错误响应不缓存。
- 读取不延长有效期；命中缓存时跳过外部请求间隔的等待。
- 席别、车次类型、实际站点及换乘条件仍按请求过滤，搜索范围和预算限制仍显示。

## 验证结果

1. 后端：`CI=true PYTHONDONTWRITEBYTECODE=1 python -m unittest discover -s backend -p 'test_*.py' -q`。
   148 项中 142 通过、6 跳过（5 项真实铁路联网、1 项需显式 PostgreSQL DSN 的集成测试）。
   包括两个接口的重叠请求、会话隔离、缓存过期/容量、失败不缓存、数据库故障回退及缓存命中免等待。
2. 前端：`npm test`，41/41；`npm run build` 成功。
3. 固定响应浏览器验证：`ui-usability.cjs` 25 个场景、`journey-regressions.cjs` 22 个场景、
   `fastest-regressions.cjs` 1 个综合场景、`query-replacement.cjs` 桌面/手机 2 个场景，共 50 个。
   覆盖查询中切换模式、同条件重新查询、旧结果晚返回、取消、移动端及原有路线展示。
4. 真实 PostgreSQL：通过 SSH 隧道单独运行 `test_query_cache_postgres`，跨独立缓存实例共享空/非空结果，
   读取不续期，精确到期后不再返回数据；仅清理该测试自己创建的键。
5. 部署配置：服务器 `bash -n` 检查脚本通过；`docker compose -f - config -q` 通过。

本机默认执行包含真实联网的完整测试时，5 个联网测试因系统 SOCKS 代理缺少支持而网络失败。
上述离线结果与下面的服务器真实接口证据分别记录，未将本机网络失败判为业务回归。
