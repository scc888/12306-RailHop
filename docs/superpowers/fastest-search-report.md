## 行为

- 将单个前缀连续查询整个72小时改为按站对、日期合并的任务队列。同一响应供全部有效前缀使用，保留晚出发但全程耗时短的路线。
- 日期任务使用首程出发到可行接续时刻的耗时下界排序，计入个人设置或当日车站参考最少换乘时间；跨午夜日期可先于耗时较长的其他候选日期。
- `max_transfers` 搜索1至上限的换乘方案，与候选发现、每层继续搜索共用请求、时间和状态上限；缺省仍为旧 `transfer_count` 的恰好次数。最大次数模式先为现有前缀安排有限的完成尝试，防止大量继续中转站对耗尽预算。
- 具有显式端点数组时，候选发现及路线搜索都会查询选中的实际端点。未提供数组的旧城市调用保留代表站逻辑与覆盖说明。中途严格使用实际电报码同站衔接。
- 候选发现优先查询历时短的相关列车，在已发现的不同经停路线之间交错选站；保留指定首程及人工指定站优先级。
- 总耗时相同时少换乘优先。原缓存、席别筛选、指定站顺序、同车运行身份、个人时间覆盖、未核实车站60分钟默认均保留。

## 验证

先观察失败再实施的主要回归：

- 32个候选、120次查询原先只得600分钟，遗漏末尾候选的165分钟路线；修复后旧exact与 `max_transfers=2` 均返回165分钟，未提高上限。
- 同站对早出发前缀原先使最后一个请求额度后的晚出发前缀丢失，原返回240分钟；修复后返回120分钟。
- 最大两次原先只返回一次换乘；修复后同时返回一次和两次，旧exact两次保持只返回两次。
- 显式非代表端点原先无法查询到路线；修复后实际端点被查询。另验证只存在于非代表端点间的相关列车可提供中转候选。
- 发现列车原先使用响应顺序而遗漏较快列车；候选上限原先被一条经停路线独占。两个失败测试均已通过。

## 边界

仍为有候选数、发现车次数、查询次数、状态数和时间限制的搜索，结果只能称本次已查范围内最快。显式端点较多会增加站对数量并共享原预算；元数据继续披露截断与覆盖限制。发现阶段尚未检查的列车或全国站对不在已查范围内。此任务未修改请求模型、车站服务、API、JourneyService或前端，也未覆盖其他执行者或用户原有改动。
